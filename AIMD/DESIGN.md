## 🗺️ System Topology & Context Map
<a id="a-systemtopologycontextmap"></a>[TOC](#toc-systemtopologycontextmap)

- **Architecture Style:** Decoupled Event-Driven Layered Overlays (DOM Delegation Architecture)
- **Primary Language Stack:** Vanilla JavaScript (ES6+), CSS3 Variables and @keyframes Engine
- **Frameworks & Core Runtimes:** Obsidian Client API, Electron / Chromium DOM Environment

---

## 💻 High-Level Components & Communication
<a id="a-highlevelcomponentscommunication"></a>[TOC](#toc-highlevelcomponentscommunication)

- **Frontend/Client:** Floating `fixed` structural canvas layer injected as structural child nodes directly into the application `document.body` matrix.
- **Backend Core:** High-frequency event tracking scheduler running at a 16ms evaluation cadence (~60fps) to compute target boundaries via `getBoundingClientRect()` coordinates.
- **External Integration:** Workspace view mutation interception hook using the native Obsidian layout-change state observer.

---

## 💾 Data Architecture & Schema Rules
<a id="a-dataarchitectureschemarules"></a>[TOC](#toc-dataarchitectureschemarules)

- **Storage Type:** Stateless Runtime Architecture with static, immutable configuration metrics defined inside `manifest.json`.
- **State Constraints:** Workspace configuration safety metrics enforced via programmatic DOM visibility overrides if tracking references disappear or layout modals intercept rendering contexts.

## 🚦 Design Principles & Guardrails
<a id="a-designprinciplesguardrails"></a>[TOC](#toc-designprinciplesguardrails)

- **Dependency Minimization:** Avoid adding external packages/libraries unless natively impossible.
- **Separation of Concerns:** Keep presentation/UI entirely decoupled from system-level business logic.
- **Security Constraints:** Strict structural sanitization metrics applied during dynamic CSS template head-space compilation to block string mutation vectors.
